# muxy M6d — CI (GitHub Actions, unsigned) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GitHub Actions workflow that, on push-to-main and every PR, builds libghostty from source
(cached by the pin), runs the Rust + Swift test suites, assembles the **unsigned** `Muxy.app`, and
uploads it as a build artifact — closing the north-star "libghostty build in CI" risk gate.

**Architecture:** One workflow `.github/workflows/ci.yml` on a macOS runner: select full Xcode (Metal
compiler), install zig 0.16.0 + stable Rust, restore/build libghostty via `scripts/build-libghostty.sh`
(cached on the script+patch hash so it builds once), `cargo test --workspace --locked`,
`cd macos && swift test`, `scripts/build-app.sh`, `upload-artifact` the `.app`. Signing is added later
(M6c) gated on a secret, so forks/PRs keep building unsigned.

**Tech Stack:** GitHub Actions (macOS runner), the committed `scripts/build-libghostty.sh` /
`build-app.sh`. Spec: `docs/superpowers/specs/2026-07-30-muxy-m6-packaging-design.md` (§M6d).

## Global Constraints

- **Runner:** `macos-15` (Xcode 16.x — matches the locally-verified libghostty recipe; reduces
  SDK/Metal-compiler mismatch risk vs. the spec's `macos-14` / Xcode 15). If `macos-15` is unavailable
  or Xcode 16 fails the ghostty build, the fallback is `macos-14` + the newest Xcode it offers — decide
  from the first real run.
- **Verification is a real Actions run** — a workflow cannot be validated locally (`act` has no macOS
  runner). Local gate = `actionlint` (static). Real gate = the workflow going green on GitHub Actions;
  expect a **push → watch → fix → repeat** loop, and the **first (cold-cache) run is slow** (libghostty
  build ~15–30 min).
- **libghostty is cached** keyed on `hashFiles('scripts/build-libghostty.sh','scripts/libghostty-darwin-install.patch')`
  (the pin lives in the script, so the key changes when the pin/patch change). Cache hit → skip the
  build; miss → run `scripts/build-libghostty.sh` and save. The 189 MB `.a` stays gitignored.
- **Unsigned.** No codesign/notarize (M6c). No secrets required — the workflow must run on PRs from
  forks. `cargo test --workspace --locked` (Cargo.lock is committed). Rust stable (no toolchain pin
  in-repo). Swift comes from the selected Xcode.
- **Scope: M6d only** — one workflow file. No changes to scripts/source; no release/tag workflow (M6e),
  no signing (M6c). Pin third-party actions to a major version (`@v4`, etc.).

## Task 1: Author `.github/workflows/ci.yml`

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Produces: a CI workflow triggered on push-to-`main` + `pull_request`, that builds/caches libghostty,
  runs `cargo test` + `swift test`, assembles + uploads the unsigned `Muxy.app`.

- [ ] **Step 1: Write the workflow.** Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:

# Cancel superseded runs on the same ref.
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  build-and-test:
    name: build + test (macOS, unsigned)
    runs-on: macos-15
    steps:
      - uses: actions/checkout@v4

      - name: Select Xcode (Metal shader compiler needs full Xcode)
        uses: maxim-lobanov/setup-xcode@v1
        with:
          xcode-version: latest-stable

      - name: Verify toolchain
        run: |
          xcode-select -p
          xcrun metal --version
          swift --version

      - name: Install zig 0.16.0
        uses: mlugg/setup-zig@v1
        with:
          version: 0.16.0

      - name: Install Rust (stable)
        uses: dtolnay/rust-toolchain@stable

      - name: Cache cargo build
        uses: Swatinem/rust-cache@v2

      - name: Cache libghostty (built once per pin/patch)
        id: libghostty-cache
        uses: actions/cache@v4
        with:
          path: |
            macos/vendor/libghostty/ghostty-internal.a
            macos/Sources/GhosttyKit/include/ghostty.h
          key: libghostty-${{ runner.os }}-${{ hashFiles('scripts/build-libghostty.sh', 'scripts/libghostty-darwin-install.patch') }}

      - name: Build libghostty (cache miss only)
        if: steps.libghostty-cache.outputs.cache-hit != 'true'
        run: scripts/build-libghostty.sh

      - name: Rust tests (whole workspace)
        run: cargo test --workspace --locked

      - name: Swift tests (MuxyCore)
        run: swift test
        working-directory: macos

      - name: Assemble unsigned Muxy.app
        run: scripts/build-app.sh

      - name: Upload unsigned app artifact
        uses: actions/upload-artifact@v4
        with:
          name: Muxy-app-unsigned
          path: dist/Muxy.app
          if-no-files-found: error
```

- [ ] **Step 2: Static-lint the workflow (local gate).** Install `actionlint` and run it:

```bash
command -v actionlint >/dev/null || brew install actionlint
actionlint .github/workflows/ci.yml
```
Expected: no output (clean). Fix any reported YAML/action/shell issues before pushing. (If `brew` isn't
available, download the `actionlint` binary from its releases — the lint is the only local gate.)

- [ ] **Step 3: Commit.**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: build libghostty + cargo/swift tests + unsigned Muxy.app artifact (GitHub Actions)"
```

## Task 2: Drive the workflow green on GitHub Actions (real-CI verification)

> This task has **no local test** — it is verified only by a real Actions run. It is inherently
> iterative (push → watch → fix → repeat) and the first run is slow (cold libghostty build). Do the
> fixes as small commits on this branch; each push re-triggers the workflow.

**Files:**
- Modify (as needed): `.github/workflows/ci.yml`

- [ ] **Step 1: Push the branch to trigger the workflow.**

```bash
git push -u origin <this-branch>
```

- [ ] **Step 2: Watch the run.**

```bash
gh run list --branch "$(git branch --show-current)" --limit 1
gh run watch "$(gh run list --branch "$(git branch --show-current)" --limit 1 --json databaseId --jq '.[0].databaseId')" --exit-status
```
Expected outcome to reach: the run concludes **success**, having built libghostty (or restored it from
cache on a later run), passed `cargo test` + `swift test`, assembled `Muxy.app`, and uploaded the
artifact.

- [ ] **Step 3: On failure, read the failing step's log, fix, re-push.**

```bash
RUN=$(gh run list --branch "$(git branch --show-current)" --limit 1 --json databaseId --jq '.[0].databaseId')
gh run view "$RUN" --log-failed | tail -80
```
Common first-run failures + fixes (apply only the ones that actually occur — do not pre-emptively add):
- **Xcode/Metal missing or wrong version** → the ghostty build fails at the `metal` step. Pin
  `xcode-version:` to a concrete `16.x` instead of `latest-stable`, or fall back to `runs-on: macos-14`.
- **zig build fails on the runner's SDK** (a newer/older macOS SDK than local) → try a different Xcode
  version; if it's an SDK-path issue, confirm `SDKROOT="$(xcrun --show-sdk-path)"` resolves in the
  runner (the script already sets it).
- **`swift test` tries to build MuxyApp before libghostty exists** → ensure the "Build libghostty" step
  precedes it (it does); on a cache hit the `.a` is restored before `swift test` runs.
- **Cache action can't save a gitignored path** → `actions/cache` caches by path regardless of
  gitignore; if the `.a` path is empty on a miss because the build step was skipped, verify the
  `cache-hit != 'true'` guard is correct.
- **Artifact upload of a large `.app`** → expected (~200 MB, the statically-linked exe); if it errors on
  size, it's fine to keep — or narrow the path. Do not remove the upload.

Repeat Steps 2–3 until the run is green.

- [ ] **Step 4: Confirm a warm-cache run is fast.** After the first green run populated the cache, the
next push (or a re-run) should **restore libghostty from cache** (the "Build libghostty" step skipped)
and finish in a few minutes. Verify the cache-hit path works:

```bash
gh run view "$RUN" --log | grep -iE "cache (restored|hit)|Build libghostty" | head
```
Expected: a later run shows a libghostty cache hit and skips the build step.

- [ ] **Step 5: Record the final green run** in the report (run URL + timing: cold vs. warm).

## Self-Review Notes (author)

- **Spec §M6d coverage:** macOS runner + Xcode + zig → Task 1 steps; build libghostty via the M6b
  script, **cached** by the pin → the cache step + `cache-hit` guard; `cargo test` (workspace) +
  `swift test` (MuxyCore) → Task 1 steps; assemble + upload the **unsigned** `.app` → build-app.sh +
  upload-artifact; runs on PRs without secrets (unsigned) → no secrets referenced; "signing added when
  M6c lands, gated on a secret" → left as a documented follow-up (not built here). Spec §Testing "the
  CI workflow goes green (libghostty cached, cargo+swift tests pass, unsigned artifact uploaded)" →
  Task 2.
- **Verification honesty:** Task 1's only local gate is `actionlint`; the *real* gate is Task 2's live
  Actions run. This is unavoidable — GitHub Actions macOS workflows cannot run locally (`act` is
  Linux-container only). Task 2 is an explicit push-and-iterate loop, and the first run is slow.
- **Runner deviation from spec:** spec said `macos-14`; this uses `macos-15` for Xcode-16 parity with
  the locally-verified libghostty recipe. The fallback to `macos-14` is documented in Task 2 Step 3.
- **Deferred / out of scope:** codesign/notarize/DMG (M6c) added to this same workflow later, gated on
  a signing secret; the tag→release workflow (M6e); Linux CI (M8). No caching of the ghostty *clone*
  (only the built `.a`); revisit if fetch time dominates.
- **Cost caveat:** each run consumes macOS Actions minutes (billed 10× Linux); the cold libghostty
  build is the long pole. The cache makes subsequent runs cheap.
